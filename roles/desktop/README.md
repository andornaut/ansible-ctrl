# ansible-role-desktop

Installs a Linux desktop environment and common applications on Ubuntu.

## Usage

```bash
make desktop
make desktop -- --tags browser
```

`desktop.yml` applies this role, then [bspwm](../bspwm/README.md) or [niri](../niri/README.md) per the host's
`desktop_environment`.

A bspwm or niri host must be in the `dev` group and have had `make dev -- --limit <host>` run first: eww and niri
build with the dev role's per-user Rust, nwg-drawer with its Go. `desktop.yml` asserts the group membership before
applying anything.

## Desktop environments

| Constraint                                   | Detail                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| gnome                                        | GNOME Shell and gdm3, without the tiling tags. GNOME has a Wayland-only session, so no Xorg server is installed; X11 apps run under XWayland                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Tiling hosts                                 | The tags marked _tiling_, plus the session tools both tiling sessions use ([tasks/apt_tiling.yml](./tasks/apt_tiling.yml)): screenshots, per-app volume, media keys and the X11 utilities. niri runs the X11 ones as XWayland clients                                                                                                                                                                                                                                                                                                                                                       |
| Display manager                              | A tiling host sets exactly one of `desktop_install_ly` and `desktop_install_lemurs`; a gnome host gets gdm3. Every other display manager is masked, gdm under both `gdm.service` and `gdm3.service`, and a `display-manager.service` alias to one of them removed, so a host can move between gnome and a tiling session. A mask that fails for any reason but the unit not being installed fails the run: a regular unit file under `/etc/systemd/system`, which `systemctl mask` will not replace, is removed by hand. The run fails rather than leave a tiling host booting to a console |
| gnome skips the tiling session tools         | GNOME has its own screenshot UI and media keys. It also goes without `pavucontrol`, although its sound panel has no per-app routing                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Window manager roles                         | Only tools with a per-protocol replacement belong to [bspwm](../bspwm/) (X11) or [niri](../niri/) (Wayland). | `ly` build                                   | Built with the newest Zig release in the series (major.minor) of the ly release's `minimum_zig_version`, read from its `build.zig.zon`: Zig breaks compatibility every minor release. The run fails when the index lists no release in that series at or above the minimum. Fetched from `desktop_zig_mirror`, a [community mirror](https://ziglang.org/download/community-mirrors.txt), because the ziglang.org origin is slow, and verified against the shasum the origin publishes. Zig is fetched only when ly is rebuilt                                                               |
| User units are wanted, not required          | `eww.service`, `nwg-drawer.service` and `desktop-idle-backstop.service` are `WantedBy=graphical-session.target`; `flameshot.service` is `WantedBy=` and `PartOf=eww.service`, so it restarts with the bar. No user unit this role writes `Requires=` the target. The target has `StopWhenUnneeded=yes`, so a unit that requires it keeps it up, and when that unit crashes every other session unit stops, the idle backstop included                                                                                                                                                       |
| The session holds `graphical-session.target` | [bspwm](../bspwm/README.md) from its session wrapper, gnome and niri from their own session. `eww` restarts on failure so the bar does not stay down until the next login                                                                                                                                                                                                                                                                                                                                                                                                                   |
| User units are enabled by symlink            | [tasks/enable_user_unit.yml](./tasks/enable_user_unit.yml) writes the symlink `systemctl --user enable` would, into `desktop_user`'s `~/.config/systemd/user/<target>.wants/`. It needs no user manager, and the unit starts at the next login                                                                                                                                                                                                                                                                                                                                              |
| Start, restart and stop need a user manager  | `systemctl --user` needs the account's manager, which runs only while the account is logged in, so these steps would fail on a host where `desktop_user` is not logged in. | Locked encrypted home                        | An encrypted home is a mount point that `getent` reports whether or not it is mounted. Writing to a locked home puts files on the mount point, reports changed, and the mount hides them at the next login                                                                                                                                                                                                                                                                                                                                                                                  |
| Home mount check                             | [tasks/main.yml](./tasks/main.yml) checks `<home's parent>/.ecryptfs/<user>`, which is outside the home and readable either way, and fails the run before any change when that home is not mounted, including without the mounts fact. Log in as `desktop_user` or run `ecryptfs-mount-private`, then re-run. A marker left by an account whose home is no longer encrypted fails the same way; remove it                                                                                                                                                                                   |

## Idle, locking and suspend

The three `desktop_screen_*_minutes` timeouts are one policy applied by three mechanisms. Only X11 distinguishes
blanking from powering the monitor down:

| Environment | Mechanism                   | Timeouts honoured      |
| ----------- | --------------------------- | ---------------------- |
| gnome       | dconf, system database      | blank, lock            |
| bspwm       | `xss-lock` and the X server | blank, lock, power-off |
| niri        | `hypridle`                  | lock, power-off        |

Under bspwm, `/usr/local/bin/xsecurelock-session` sets the timeouts once per session from the autostart entry at
login. Nothing reloads them, so a change takes effect at the next login.

| Constraint                                                                                                                     | Detail                                                                                                                                                                                                                                                                                                                       |
| ------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Blanked is not locked                                                                                                          | X11 blanking takes no keyboard grab, so between blank and lock a keystroke wakes the screen and also reaches the focused window. Set `desktop_screen_lock_minutes` equal to `desktop_screen_blank_minutes` to remove that gap, at the cost of the period where returning needs no password                                   |
| GNOME lock prerequisites ([tasks/idle.yml](./tasks/idle.yml))                                                                  | The lock depends on six keys, not `lock-enabled` alone. `screensaver/idle-activation-enabled` must be true for the screensaver to activate, and `lockdown/disable-lock-screen` false for a lock to be allowed. Without them a host with `lock-enabled` set can leave the session unlocked                                    |
| GNOME lock timing keys                                                                                                         | `screensaver/ubuntu-lock-on-suspend` locks on resume. `session/idle-delay` at 0 disables the screensaver, and `screensaver/lock-delay` leaves the session unlocked that long after blanking, so the role sets both                                                                                                           |
| GNOME power entries on the lock screen                                                                                         | Once a second user holds any session, SSH included, logind answers `CanPowerOff` and `CanReboot` with `challenge`: the action becomes `*-multiple-sessions`, which defaults to admin authentication. gnome-shell hides both entries on the lock screen when the answer is `challenge`, because the lock screen cannot prompt |
| Polkit rule ([files/50-ansible-role-desktop-lock-screen-power.rules](./files/50-ansible-role-desktop-lock-screen-power.rules)) | Grants an active local session the two actions, so gnome-shell shows the entries. Suspend has no multiple-sessions action, so Suspend stays on the lock screen                                                                                                                                                               |
| GNOME policy is locked ([templates/dconf-idle-locks.j2](./templates/dconf-idle-locks.j2))                                      | A lock makes the system value authoritative and the key unwritable, so every account that logs into GNOME gets the policy and none can turn it off. An unlocked default would sit below values an account already set, and `desktop_user` already sets these keys.                                                           |
| Suspend keys are locked only where managed                                                                                     | A lock on a key no database defines fixes it at the schema default                                                                                                                                                                                                                                                           |
| Locks only on gnome                                                                                                            | A leftover default can be changed from Settings; a leftover lock makes the key unwritable until the file is deleted and the database recompiled. `00-idle`, `01-keyboard` and their lock files are removed where `desktop_environment` is not `gnome`                                                                        |
| `XSECURELOCK_*` settings ([templates/xsecurelock-session.j2](./templates/xsecurelock-session.j2))                              | `FORCE_GRAB=1` forces the grab, so a fullscreen game or open menu cannot keep the session from locking. `DISCARD_FIRST_KEYPRESS=1` drops the key that dismisses the blank screen, so a password is not typed at a black screen. Authentication needs nothing setuid (`common-auth` PAM service, `unix_chkpwd`)               |

### Suspend

`desktop_suspend_inactive_minutes` is a separate policy. `logind` cannot detect idleness, so GNOME uses
`gnome-settings-daemon`, niri a `hypridle` listener, and bspwm has `xss-lock` set the session's idle hint when the
X screensaver activates.

| Constraint                        | Detail                                                                                                                                                                                                                                                                                                                  |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| bspwm `logind` drop-in            | Gets `desktop_suspend_inactive_minutes` minus `desktop_screen_blank_minutes`, because `IdleActionSec` counts from the idle hint, which is set at blank time. The variable means "suspend this long after the last input" on every desktop, and must be 0 or greater than the blank timeout (asserted by the `idle` tag) |
| bspwm policy is host-wide         | An idle `ssh` login also delays suspend. The drop-in is removed from a host that moves off bspwm                                                                                                                                                                                                                        |
| niri value is in a shared dotfile | It renders into `.config/hypr/hypridle.conf`, a dotfiles symlink. Two niri hosts with different values overwrite each other's managed block. Give niri hosts the same value, or move to a role-owned per-host file like the bspwm drop-in                                                                               |

### Idle backstop

Every mechanism above honours idle inhibitors, and none limits how long one is held. Any application can take one
through `org.freedesktop.ScreenSaver` (GNOME), `XScreenSaverSuspend` (X11) or `idle-inhibit-unstable-v1` (Wayland).
A game usually holds one for its whole run: GameMode does by default, and SDL and GLFW do for any window they open,
so the panel shows a static image for as long as the game runs. `desktop_idle_backstop_minutes` powers the panel
down after that many minutes without input, whatever holds an inhibitor.

`desktop-idle-backstop.service`, a user unit wanted by `graphical-session.target`, polls the idle time that
`desktop-idle-input` measures from the input devices, and powers the panel down from outside the compositor. Every
environment reads that source; only the power-off command differs:

| Environment | Powers the panel down with                                                                                       |
| ----------- | ---------------------------------------------------------------------------------------------------------------- |
| gnome       | `ddcutil setvcp d6 04`, then `d6 01` on the next input                                                           |
| bspwm       | `xset dpms force off`, which the X server reverts on input                                                       |
| niri        | `niri msg action power-off-monitors`, which [templates/hypridle.conf.j2](./templates/hypridle.conf.j2) also uses |

| Constraint                                          | Detail                                                                                                                                                                                                                                                                                                                                           |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Compositor idle times are not used                  | Each can be held below any threshold by inhibitors: mutter resets `GetIdletime` when an inhibitor is released, the X server resets the `XScreenSaverQueryInfo` idle time for any client calling `XResetScreenSaver`, and niri exposes only `ext-idle-notify-v1`, which inhibitors suppress                                                       |
| `desktop-idle-input.service`                        | Watches the input devices and writes the time of the last input to `/run/desktop-idle-input/stamp`, independent of the compositor. Installed on every desktop host, beside the backstop                                                                                                                                                          |
| The reader is a root system service                 | Reading the devices as the session's account would need the `input` group, which lets every process of that account read every keystroke, including under Wayland, where a client otherwise cannot. The service publishes only a time, never which key was pressed                                                                               |
| Stamp heartbeat                                     | A dead reader leaves the idle time frozen, which looks like an idle session and would blank a panel in use. The backstop rejects a heartbeat older than `desktop_idle_input_stale_seconds` or ahead of its own clock, and exits so systemd restarts it. A reader with no device to watch publishes nothing, so its stamp goes stale the same way |
| Idle clock stops during suspend                     | The reader measures idle time on a clock that does not advance while the host is suspended. With the wall clock, a resume would read as the whole suspended period, past any threshold, and the panel would power off as the user returned                                                                                                       |
| `EV_ABS` and key autorepeat are not input           | Both occur with no user present: stick drift emits `EV_ABS` continuously, and a held key autorepeats. A controller, or an object resting on the keyboard, beside a running game is the case the backstop is for. Touchpads, touchscreens and tablets report a `BTN_*` key event on contact, so they still count                                  |
| gnome uses DDC/CI, not DPMS                         | GNOME is Wayland-only, so only mutter can control an output. `d6 04` is DPM off; the panel still answers on the bus in that state, so `d6 01` turns it back on without its power button. A monitor that implements neither cannot be backstopped; `ddcutil capabilities` lists the values `d6` accepts                                           |
| Threshold above `desktop_screen_blank_minutes`      | Asserted by the `idle` tag. Below the blank timeout the backstop would act before the session's own blanking                                                                                                                                                                                                                                     |
| Not limited by `desktop_suspend_inactive_minutes`   | An inhibitor defers idle suspend as well as blanking, so a backstop longer than the suspend timeout still fires when suspend cannot. When nothing inhibits, the host suspends first                                                                                                                                                              |
| DDC writes need no root or extra group              | `ddcutil`'s udev rule tags the I2C device `uaccess`, so the local session's user gets the bus and loses it when the session ends. `ddcutil` also ships the `modules-load.d` entry for `i2c-dev`. Only the reader runs as root                                                                                                                    |
| Panel restored on stop                              | Left in DDC standby, the panel stays dark into the next login                                                                                                                                                                                                                                                                                    |
| Exits after three failed idle reads                 | A failed read means the reader is gone or its stamp is stale. With no idle time it has nothing to enforce, so it exits and systemd restarts it, which reconnects it to the reader. Repeated restarts in the journal mean the backstop is not enforcing anything                                                                                  |
| A failed wake is retried, a failed power-off is not | A dark panel while someone is typing is the worse failure. A failed power-off is usually a panel that already powered down on its own and stopped answering, and `ddcutil` retries the write itself                                                                                                                                              |
| Poll interval                                       | 30s while the panel is on, 2s while it is off. The 2s interval is the wake latency at the keyboard                                                                                                                                                                                                                                               |

## Parental controls

Web filtering is enforced in the name service switch, not the browser. `nss-malcontent` returns a sinkhole address
for a blocked hostname to users with a compiled filter list under `/var/lib/malcontent-webd/filter-lists/`, and
passes every other lookup on. The `/etc/nsswitch.conf` edit is system-wide; the policy is per-user.

| Constraint                                          | Detail                                                                                                                                                                                                                                                                                                                                                        |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Exact hostname matching                             | The filter is a cdb keyed on whole hostnames: no wildcards or subdomains. Lists must be plain newline-separated bare hostnames served over HTTPS. One malformed line aborts the update and keeps the previous list                                                                                                                                            |
| `use-application-dns.net` is blocked for every user | This canary disables DoH in Firefox, which would otherwise resolve names without the module                                                                                                                                                                                                                                                                   |
| Chrome policy directory                             | Chrome merges every file in `/etc/opt/chrome/policies/managed/` and the later name wins, so a `family.json.bak` outranks the original. The role owns the directory and removes any file it did not deploy                                                                                                                                                     |
| Empty lists are rejected                            | The role asserts the chosen list type has entries: an empty allow list blocks everything, and an empty block list filters nothing while reporting the filter as on                                                                                                                                                                                            |
| Flatpak installation permissions                    | Both are passed explicitly: setting any OARS ceiling also disallows installs from the system repository, which the role re-allows when it clears the filter                                                                                                                                                                                                   |
| Flag off clears the controls                        | The tag runs on every desktop. With `desktop_install_parental_controls` false it clears both `malcontent` filters and removes the Chrome policy; the `browser` tag drops the Firefox parental policies. Also remove the host's `desktop_parental_controls_*` settings: the role asserts the OARS ceiling and web filter type are unset when the flag is false |
| Firefox parental policies                           | `policies.json` gets `DisablePrivateBrowsing` and a locked `DNSOverHTTPS` with `Enabled: false`, from the `browser` tag. The file has no per-user scope, so both apply to every account on the host, not only the filtered one                                                                                                                                |
| Flatpak browsers bypass the web filter              | `nss-malcontent` is loaded through the host's `/etc/nsswitch.conf`, which a flatpak runtime does not read. The default Firefox is a flatpak, as is any browser the filtered account installs itself, which the app filter's `--allow-user-installation` keeps permitted. DNS filtering at the router is what covers them                                      |
| `malcontent-webd-update.service` override           | The packaged unit is `WantedBy=multi-user.target` with no network ordering, so the boot fetch fails with 69/UNAVAILABLE before a resolver answers, and the unit stays failed until the timer's `OnBootSec=15min` run. The role adds a `network-online.target` drop-in                                                                                         |

## Notes

| Constraint                               | Detail                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| systemd-networkd                         | Stopped and disabled, since its wait-online unit times out on NetworkManager's links. Left running where netplan renders a link with it (a `.network` file under `/run/systemd/network` or `/etc/systemd/network`)                                                                                                                                                                                                                                                                                                      |
| dconf keyboard policy                    | Written to `/etc/dconf/db/local.d` and locked in `local.d/locks/`, so it applies to every account and none can change it. `dconf-cli` and `python3-psutil` are installed on every desktop. The Ubuntu Dock setting is `desktop_user`'s only; the lock and idle policy belongs to the `idle` tag                                                                                                                                                                                                                         |
| Dotfiles that may be symlinks            | A path that may be a dotfiles symlink, such as `.config/hypr/hypridle.conf`, is not written with `template` or `copy`: when unchanged they re-run the `file` module on the resolved target, and `file` expands `$HOME` in that path, corrupting a repo tree under a directory named `$HOME`. `blockinfile` writes through the link instead                                                                                                                                                                              |
| Dangling dotfile links                   | [tasks/idle_check_dotfile.yml](./tasks/idle_check_dotfile.yml) classifies the path before writing and fails on a dangling link, so the link target is not replaced by a regular file                                                                                                                                                                                                                                                                                                                                    |
| nwg-drawer build and toggle              | Built with the dev role's Go and kept running under a user unit. `pkill -USR1 -x nwg-drawer` toggles the window; the sxhkd dotfile binds it. On X11 it opens an undecorated maximized window, so the bspwmrc dotfile has a fullscreen rule for it                                                                                                                                                                                                                                                                       |
| nwg-drawer categories                    | Buttons use the GNOME app grid's folder names (Utilities, System), not the menu spec's (Accessories, System Tools). Only the names are shared: the drawer files entries by freedesktop category, the GNOME grid by the ids in its folder map                                                                                                                                                                                                                                                                            |
| nwg-drawer Hobbies button                | Buttons sort by label, except the last (upstream's Other), which is pinned and relabelled Hobbies. It holds every entry whose categories match no other button; the override maps put the electronics, FPV, CAD and 3D printing tools there                                                                                                                                                                                                                                                                             |
| keyboard-configurator scope              | Replaces the vendors' rule files, which grant the whole keyboard. A keyboard interface the user can open is one a game's Wine opens as a HID device and reads keys from, below the kernel keymap and every XKB remap                                                                                                                                                                                                                                                                                                    |
| Raw HID interface detection              | The raw interface is the one with no input device beside it. USB interface protocol does not identify it: a QMK NKRO interface is protocol 00 and is a keyboard                                                                                                                                                                                                                                                                                                                                                         |
| keyboard-configurator grants are revoked | The rule flushes the other interfaces' ACLs, and the handler re-adds every raw HID node and flushes any that comes back untagged, so a grant is removed with the rule or list entry that made it                                                                                                                                                                                                                                                                                                                        |
| Flatpak overrides are written whole      | Each `--user` override this role owns (every application in `desktop_flatpak_apps`, the Firefox flatpak, and the global theme override) is reset and then reapplied from `desktop_flatpak_overrides` or the theme variables, so a grant dropped from the map is revoked and a manual `flatpak override --user` or Flatseal edit is lost on the next run. The games role converges its own applications' overrides the same way; no application is in both roles' lists                                                  |
| App entry overrides                      | An override is the packaged entry copied with one field changed, so `Exec` and actions follow the package. An id with no entry on the host is skipped, and an override that a role's map no longer names is removed. The dev, games and hobbies roles have a map of the same shape                                                                                                                                                                                                                                      |
| Release builds are version-checked       | dunst, rofi, nwg-drawer, ly and lemurs are rebuilt or downloaded only when the installed binary's `--version` (`-v`) differs from the latest release tag. Build dependencies, the Go probe included, are installed only for a rebuild; the libraries each binary links against are installed every run. lemurs' `config.toml`, `lemurs.service` and `xsetup.sh` are refetched from the same tag with the binary. eww and pavolume build from a branch, which no version output identifies, so they rebuild on every run |
| Source builds run as `desktop_user`      | dunst, rofi, nwg-drawer, ly, eww and pavolume are downloaded and built by `desktop_user` in a temporary directory; only the install steps run as root. eww needs that account's `cargo`                                                                                                                                                                                                                                                                                                                                 |
| Release architectures                    | lemurs publishes an `x86_64` build only, and the role asserts one exists for the host. Chrome and LACT take the Debian name from `desktop_arch`                                                                                                                                                                                                                                                                                                                                                                         |
| WirePlumber `audio.format`               | For a device that cannot sustain its advertised format, such as a USB microphone that stalls seconds into every capture at its full bit depth and runs indefinitely at a lower one. Used instead of a card profile, which the profile last selected in a volume-control UI overrides                                                                                                                                                                                                                                    |
